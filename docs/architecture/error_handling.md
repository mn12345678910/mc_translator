# 錯誤處理

本專案在翻譯流程中採「記錄日誌 + 保持流程可用」的策略，只有重大錯誤會中止流程。

## 錯誤分級

- 可恢復: 例如單批次失敗，會進入降級重試
- 不可恢復: 例如 API 重大錯誤或超時，會直接回傳 Err

## 批次翻譯降級

- 初次批次失敗 -> 批次大小與字元上限減半重試
- 二次失敗 -> 單筆翻譯
- 單筆失敗 -> 記錄錯誤日誌，流程繼續處理其餘項目

## 常見錯誤來源

- 讀取檔案失敗 (JSON/JS/JAR)
- JSON 格式錯誤
- API 回應錯誤或逾時
- 解析翻譯結果失敗

## 日誌紀錄

- 進行中日誌由 `add_log_event` 生成
- `enable_debug_log` 會將日誌寫入 `logs/debug.log`
- GUI 會同步顯示日誌

## CLI 行為

- CLI 會在標準輸出顯示錯誤訊息
- 若輸入路徑不存在，會直接提示並返回

## GUI 行為

- 發生錯誤後會推送 `translation-finished` 事件
- 若有錯誤詳細資訊會寫入日誌區
