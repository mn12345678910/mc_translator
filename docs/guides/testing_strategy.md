# 專案測試規範與策略 (Testing Strategy)

為了確保程式碼的穩定性與安全性，本專案必須嚴格遵守以下測試規範。

## 1. 三項測試規則 (3-Test Rule)
每一項獨立的功能模組必須分別通過至少三個方向的測試：

1.  **正常路徑測試 (Happy Path)**：驗證功能在標準輸入下的正確性。
2.  **邊界值測試 (Edge Cases / UTF-8)**：
    *   驗證空輸入、極大輸入。
    *   **強制要求**：必須包含包含特殊字元（如 Unicode、表情符號、繁體/簡體中文互轉）的 UTF-8 測試。
    *   **Unicode 安全規範**: 所有測試中的中文硬編碼字串應統一使用 Unicode 轉義序列 (如 `\u{4f60}`)。
3.  **強韌性與異常處理 (Robustness / Negative Cases)**：
    *   驗證錯誤輸入如何處理。
    *   驗證潛在的無限迴圈輸入（如遞迴呼叫的關鍵節點）。

## 2. 防止無限迴圈 (Infinite Loop Prevention)
測試必須包含對遞迴邏輯的安全性檢查。
-   **翻譯引擎**：必須提供具備最大深度或「已處理標記」的測試案例。
-   **辭典替換**：測試「A -> B, B -> A」這種循環替換是否會導致程式崩潰。

## 3. 強制 UTF-8 處理
所有檔案讀寫與文字處理都必須在測試中驗證對 UTF-8 的支援。
-   禁止使用會遺失編碼資訊的處理方式。
-   測試需模擬包含亂碼或混合編碼時的防錯機制。

## 4. 測試環境與位置
-   **環境設定 (Windows Native)**：
    *   直接在 Windows Native 底下使用 `cargo test` 運行。
    *   整合測試若呼叫 Ollama API 或實機掃描，應使用 `#[ignore]` 標記。
-   **測試放置位置**：
    *   **單元測試**：放置於 `src/` 各檔案末尾的 `mod tests` 中。
    *   **整合測試**：放置於 `tests/` 目錄下（測試公開 API 與模組協作）。
