# 語言檔案比對機制 (Comparison Mechanism)

當系統在掃描階段發現**來源語言檔案**（如 `en_us.json`）與**目標語言檔案**（如 `zh_tw.json`）**同時存在**時，會透過遞迴方式進行智慧型比對，以決定哪些項目需要送交翻譯。

---

## 🔍 比對流程

### 1. 鍵（Key）的對齊
系統會依照來源語言的 JSON 階層（Object 或 Array），逐一檢查同一個位置的目標語言內容（`zh_tw_base`）。
* **來源有，目標沒有**：視為全新項目，送交翻譯。
* **來源有，目標也有**：進入值（Value）內容比對。
* **💡 與順序無關**：對於最常見的鍵值對（JSON Object）結構，系統是以**「鍵（Key）的名稱」**進行精確搜尋（而非行號），因此排列順序不同**完全不影響**比對。

### 2. 值（Value）的內容篩選
對於每個 String 項目，系統套用以下規則決定是否「沿用」或「重翻」：

| 比對情境 | 目標語言的數值（Existing Value） | 比對結果與處理 |
| :--- | :--- | :--- |
| **已有正常翻譯** | 目標值 **非空白** 且 **與來源不同** | **✅ 直接沿用**。視為已翻譯過，不重複翻譯以節省費用。 |
| **尚未翻譯（純複製）** | 目標值 **與來源完全相同** | **🤖 送交 AI 翻譯**。認為該項目只是從來源複製來，尚需處理。 |
| **未定義（空白或缺失）** | 目標值為 空白 或 該項不存在 | **🤖 送交 AI 翻譯**。 |

---

## 📌 附加過濾規則
在確認需要翻譯前，系統會呼叫 `should_skip_key` 與 `should_skip_value`：
* **略過數字 / 空白 / 純符號**（如 `"123"`, `"... "`）。
* **略過系統特定黑名單 Key**。

---

## 💡 效益
1. **節省成本與時間**：大幅減少呼叫 API 的重複文字量。
2. **增量更新（Incremental Update）**：模組更新後新增的 Key 會自動被挑出翻譯，原有的優質翻譯則能安全保留。
