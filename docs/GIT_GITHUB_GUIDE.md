# Git 與 GitHub 使用指南 (Git & GitHub Guide)

這份報告旨在幫助您理解 `mc_translator_rs` 專案中版本控制的核心概念與操作流程。

## 1. 核心觀念：Git vs. GitHub

| 特性 | Git (引擎/日記本) | GitHub (雲端/圖書館) |
| :--- | :--- | :--- |
| **位置** | 您的電腦 (本地) | 網際網路 (雲端) |
| **功能** | 紀錄檔案變更、還原版本。 | 備份代碼、多人協作、保存歷史。 |
| **運作** | 離線也能運作。 | 需要網路才能同步。 |
| **同步性** | **手動**進行 Commit。 | **手動**進行 Push。 |

---

## 2. 標準開發工作流 (The workflow)

當您修改了程式碼後，請遵循以下步驟：

1.  **修改檔案**：在編輯器中完成您的代碼工作。
2.  **暫存變更 (Add)**：選取哪些檔案要寫入這次的紀錄。
    *   指令：`git add .` (代表加入所有修改過的檔案)
3.  **正式存檔 (Commit)**：給這次的變更寫下一段有意義的說明。
    *   指令：`git commit -m "修正了某個 Bug"`
    *   *註：這只是存進您電腦的 .git 資料夾裡。*
4.  **上傳雲端 (Push)**：把本地的紀錄同步到 GitHub。
    *   指令：`git push`
    *   *註：執行這步後，GitHub 網頁上的代碼才會更新。*

---

## 3. 為什麼不是「自動同步」？

Git 的設計哲學是 **「有意義的存檔」**。
*   自動同步會導致您的歷史紀錄充斥著「寫到一半」、「程式碼崩潰」的片段。
*   手動 Commit 讓您可以確保每一個「存檔點」都是穩定且可運作的。
*   這就像寫書：暫存是草稿，Commit 是定稿，Push 是出版。

---

## 4. 針對 AI 協作的特別建議

當您開啟新的對話 (New Session) 或切換 AI 助理時：
*   **先 Commit 再離開**：確保工作區是乾淨的 (`git status` 顯示無變動)，這樣新的 AI 就能從最穩定的基點開始。
*   **引導 AI 讀取紀錄**：您可以對 AI 說：「請讀取 `git log` 與 `MAINTENANCE_LOG.md` 以了解進度。」
*   **利用分支 (Branch)**：如果您要 AI 下重手大幅修改代碼，請先執行 `git checkout -b <新分支名>`。如果改壞了，隨時可以切換回 `main` 分支當作沒發生過。

---

## 5. 常用救急指令

*   **「我剛才改亂了，想回到上次存檔的樣子」**：  
    `git restore .`
*   **「我想看之前的存檔紀錄」**：  
    `git log --oneline`
*   **「我想確認目前有哪些檔案還沒存檔」**：  
    `git status`
